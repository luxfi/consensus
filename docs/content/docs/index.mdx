# Lux Consensus

Lux finality is leaderless. Each validator signs one fixed byte string over one
position; any node holding enough of those signatures assembles the same
certificate. Nothing is aggregated, no secret share is combined, and building a
certificate needs no secret — so there is nothing for a leader to be.

Acceptance is decided by metastable sampling to β-confidence. A certificate is the
portable witness of that decision, not a second decider.

- [Conformance](/docs/conformance) — Go is the network; how Rust and C++ are held to it.

## The ladder

A block carries exactly one rung, and the rungs are distinct authorization
boundaries that are never collapsed into one another.

```text
photon → wave → nova → quasar → horizon
```

**Nova** is a strict majority of stake. It authorizes local execution and is
reorgable — a lone equivocator can fork a bare majority. **Quasar** is a strict two
thirds of stake by distinct signers. It is the export rung: bridges, DEX
settlement, cross-chain messages, validator-set transitions. **Horizon** adds a
post-quantum seal and is irreversible.

The invariant: a block below quasar may drive local execution and may never be
exported as final.

## Three implementations, one rule

`luxfi/node` (Go) runs mainnet, testnet and devnet — `chains/manager.go` builds
`engine/chain` and injects a BLS vote verifier. The Rust and C++ implementations
are correct exactly insofar as they reproduce what it produces, byte for byte.

That is not a reading exercise. `conformance/corpus.json` is the standard as data,
projected from the live Go definitions, and an implementation is conformant when it
reproduces that file. Two real divergences were found this way and are described
in [Conformance](/docs/conformance) — a C++ vote message that was 70 bytes under a
v1 tag where Go signs 226 under v2, and a Rust θ that accepted on eleven votes
where Go requires fifteen.

## Quick start

```bash
go get github.com/luxfi/consensus@latest
```

The root package is the small block-and-vote surface. The protocol packages under
`protocol/` and the production engine under `engine/chain/` are imported directly.

```go
package main

import (
	"context"
	"fmt"

	"github.com/luxfi/consensus"
	"github.com/luxfi/ids"
)

func main() {
	// Alpha is the quorum: how many distinct voters must name a block.
	chain := consensus.NewChain(consensus.Config{Alpha: 3})

	ctx := context.Background()
	if err := chain.Start(ctx); err != nil {
		panic(err)
	}
	defer chain.Stop()

	block := consensus.NewBlock(ids.ID{0x01}, consensus.GenesisID, 1, []byte("hello"))
	if err := chain.Add(ctx, block); err != nil {
		panic(err)
	}

	for _, voter := range []consensus.NodeID{{0x0a}, {0x0b}, {0x0c}} {
		if err := chain.RecordVote(ctx, consensus.NewVote(block.ID, consensus.VoteCommit, voter)); err != nil {
			panic(err)
		}
	}

	fmt.Println(chain.IsAccepted(block.ID)) // true
}
```

## Post-quantum finality

Horizon is reached when a post-quantum signature seals the certificate. The rule
does not change at that rung — only the cryptography of the witness.

`protocol/quasar` runs its signing paths in parallel rather than in sequence:
BLS12-381 threshold signatures on ECDL hardness, Corona two-round threshold on
Ring-LWE, ML-DSA-65 (FIPS 204) identity signatures on Module-LWE and Module-SIS,
and an SLH-DSA (FIPS 205) hash-based leg. Each layer is independently toggleable.
An adversary against the full set must break all of those assumptions at once.
